# ADR-018 — Personal Identity, Session, and Actor Primitives

**الحالة:** مقبول في Phase 2A.1.

## السياق

يستخدم DentPilot نموذج ملكية شخصي، ولذلك يساوي المستخدم البشري المالك الفعلي لموارد حالاته ووسائطه ومشروعاته ووظائفه. كانت Foundation تستخدم محول تطوير مؤقتًا لتوفير هذا الممثل، لكنها لا تقدم بعد مصادقة HTTP أو تسجيلًا أو تسجيل دخول.

## القرار

تُخزن الهوية الأساسية في `users` عبر البريد الأصلي والبريد المطبع `normalizedEmail` وحالة الحساب ووقت تحقق البريد. تحفظ كلمات المرور في جدول واحد `password_credentials` لكل مستخدم باستخدام Hash Argon2id فقط. تحفظ الجلسات والرموز الحسابية opaque tokens في شكل SHA-256 فقط؛ يعاد النص الصريح عند الإنشاء ولا يحفظ في PostgreSQL.

يفصل سجل التدقيق بين ممثل بشري يملك `actorUserId` وممثل نظامي يملك `systemActorKey`. لا ينسب العامل النظامي أفعاله إلى مستخدم بشري. يظل `ownerUserId` مفتاح ملكية الرسم الشخصي، لا توصيفًا للممثل.

## القيود الأمنية

يفرض PostgreSQL uniqueness للبريد المطبع وdigest الرموز والجلسات، ويفرض مدة إيجابية للجلسات والرموز وشكل SHA-256، ويمنع أشكال ممثل التدقيق المختلطة. تستخدم طبقة البنية Argon2id بمعلمات مركزية متحققة. يسجل التطبيق قيمًا حساسة بصيغة محجوبة ولا يقدم في هذه المرحلة أي endpoint للمصادقة أو cookie أو JWT أو OAuth أو استعادة كلمة مرور عبر HTTP.

## النتائج

توجد الآن بدائيات متينة لتبني Phase 2A.2 فوقها. يحتفظ محول التطوير المؤقت بمسار Foundation فقط ويستخدم مستخدمًا حتميًا غير قابل للتوجيه، على أن يزال عند تركيب المصادقة الحقيقية.
