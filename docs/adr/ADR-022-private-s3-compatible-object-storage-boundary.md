# ADR-022: حد تخزين كائنات خاص ومتوافق مع S3

## السياق

تعامل DentPilot صورًا خاصة، بينما كان التنفيذ السابق مقيدًا بنظام ملفات محلي وبعقد بايتات غير مناسب لتشغيل إنتاجي. لا يجوز أن تصبح هوية الكائن أو عنوانه أو بيانات اعتماد التخزين جزءًا من عقد العميل أو قرار التفويض.

## القرار

يُعتمد `ObjectStoragePort` متدفق ومحايد للمزود، مع محولي `LocalObjectStorageAdapter` للتطوير والاختبار و`S3ObjectStorageAdapter` للإنتاج. يختار التكوين الصريح `OBJECT_STORAGE_DRIVER=local|s3` المحول. يقدّم العقد فقط تدفقات وبيانات وصفية آمنة (`contentLength` و`contentType` و`etag` عند وجوده) والحذف وفحص الجاهزية.

## السبب

يبقى PostgreSQL سجل الملكية والحالة، فيما يكون التخزين الخاص مخزن كتل فقط. يقلل العقد المتدفق اقتران التطبيق بنظام الملفات ويمكّن S3 وMinIO من غير منطق مزود داخل الخدمات. لا يُستخدم ETag كدليل SHA-256؛ تجزئة DentPilot المستقلة هي مرجع سلامة المصدر.

## النتائج

لا يضبط محول S3 أي ACL عام، ولا يعيد مفاتيح أو عناوين كائنات أو بيانات اعتماد. يجب أن يحجب نشر الإنتاج الوصول العام للحاوية وأن يفعّل التشفير الساكن لدى مزود التخزين. يمكن تمرير تشفير S3 من جانب الخادم اختياريًا إذا كان الموفر يدعمه. يرفض الإنتاج تخزينًا محليًا أو تكوين S3 الناقص، ويفحص تشغيل API وصول الحاوية باستخدام `HeadBucket` من دون إنشائها.

## البدائل المدروسة

رُفض ربط الخدمات مباشرةً بـ AWS SDK لأنه يعزل التطبيق عن MinIO والموفرين المتوافقين. ورُفض الاعتماد على عناوين كائنات أو ACL كحل تفويض لأنه يتجاوز سجل الملكية وقواعد العزل في PostgreSQL.
