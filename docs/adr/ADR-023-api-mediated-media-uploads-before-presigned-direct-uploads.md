# ADR-023: رفع وسائط عبر API قبل التحميل المباشر الموقّع

## السياق

تحتاج مرحلة الوسائط إلى التحقق من الملكية والبايتات والنوع والأبعاد والتجزئة والحالة قبل التزام مصدر خاص. التحميل المباشر إلى S3 يضيف سطح تهديد وإدارة مفاتيح وسياسات دورة حياة واسترداد أكبر من المطلوب في هذه المرحلة.

## القرار

تبقى بنية الرفع في Phase 3 عبر API. لا تنفذ هذه المرحلة عناوين رفع جديدة أو روابط S3 موقعة أو تحميلًا مباشرًا أو رفعًا قابلًا للاستئناف. ينشئ الخادم هوية التخزين ومفاتيح التدريج فقط، وتحافظ قاعدة البيانات على حالتها الدائمة.

## السبب

تتيح الوسائط المحدودة الحجم أن يتحكم API بالبايتات وبالتفويض. كما تحفظ هذه البنية نقطة فرض واحدة تمنع العميل من التحكم بمفتاح التخزين أو ادعاء ملكية مورد أو استخدام URL كدليل وصول.

## النتائج

سيكون رفع multipart المتدفق والتحقق النهائي جزءًا من Phase 3B، مع استخدام حالة الجلسة ومفتاح الإحاطة المضافين في Phase 3A. إذا بررت قياسات الحجم أو معدل النقل تغييرًا لاحقًا، يقتضي التحميل المباشر ADR جديدًا يتناول آلية التوقيع والتحقق والتدريج والتنظيف وحدود الإساءة.

## البدائل المدروسة

رُفض التحميل الموقّع المباشر في هذه المرحلة لأنه يوسع نموذج التهديد سابقًا لأوانه. ورُفض إدخال منطق S3 داخل العميل لأنه يكشف تفاصيل مزود التخزين ويكسر سلطة الخادم على هوية الكائن.
