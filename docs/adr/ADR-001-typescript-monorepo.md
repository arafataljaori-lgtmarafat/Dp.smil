# ADR-001 — TypeScript Monorepo

**الحالة:** مقبول في Phase 0.

## السياق

يحتاج المنتج المحمول وAPI وعقود النقل وقواعد المجال إلى تطور متزامن من دون تكرار تعريفات أو تشعبات غير مرئية.

## القرار

يعتمد المشروع مستودع pnpm/Turborepo أحاديًا بـ TypeScript صارم، مع تطبيقات تحت `apps` وحزم `domain` و`application` و`contracts` تحت `packages`.

## السبب

يسمح القرار بتشارك عقود Zod وأنواع المجال، وبفرض ترتيب بناء وفحص عبر الحدود بدل نسخ DTO بين التطبيقين.

## النتائج

يستلزم القرار عناية بإصدارات الحزم واتجاه الاعتماد. لا يجوز أن يتحول المستودع إلى تطبيق واحد ضخم؛ تبقى الحدود حزمًا مستقلة.

## البدائل

رُفضت مستودعات منفصلة لأنها تضيف نشرًا متبادلًا وتكرارًا للعقود مبكرًا، كما رُفض مشروع واجهة فقط لأنه لا يحقق مسار Phase 1 الخادمي الحقيقي.
