# ADR-012 — Idempotency Key + Request Fingerprint Semantics

**الحالة:** مقبول في Phase 1.1.

## السياق

مفتاح فريد على مستوى المستخدم المالك وحده قد يعيد وظيفة تخص طلبًا مختلفًا من دون إشعار.

## القرار

تخزن كل `GenerationJob` مفتاح إديمبوتنسية وبصمة SHA-256 لتمثيل قانوني ثابت يشمل `ownerUserId` والمشروع ووسيط المصدر وSHA-256 المصدر ونوع التوليد والمزود وإصدار عقد التوليد. يفرض PostgreSQL فهرسًا فريدًا على `(ownerUserId, projectId, idempotencyKey)`.

## السبب

يعيد تكرار المفتاح والبصمة نفسيهما الوظيفة الأصلية ولا يعيد إرسال المهمة أو حدث التدقيق. يرفع تكرار المفتاح ببصمة مختلفة `IDEMPOTENCY_CONFLICT` ولا يعيد وظيفة خاطئة.

## النتائج

تستلزم عمليات التوليد حساب البصمة قبل الإدراج ومقارنة البصمة المعادة بعد upsert. السباق يحكمه PostgreSQL لا واجهة المستخدم.

## البدائل المدروسة

رُفض المفتاح العالمي للمستخدم المالك، ورُفض الاعتماد على بحث ثم إدراج غير ذري، ورُفض إدخال الطابع الزمني في البصمة.
