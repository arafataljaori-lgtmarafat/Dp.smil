# ADR-019 — Opaque Bearer Authentication, Default-Deny API, and Persistent Auth Rate Limits

**الحالة:** مقبول في Phase 2A.2.

## السياق

أثبتت Phase 2A.1 مخطط الهوية والجلسات والرموز الحسابية، لكنها لم تجعل HTTP يستخرج هوية مستخدم حقيقي. كانت مسارات Foundation تعتمد ممثل تطوير مؤقتًا، وكان يلزم استبداله دون جعل ملكية الموارد معتمدة على قيم يرسلها العميل. كما أن حدود المعدل داخل الذاكرة لا تصمد أمام إعادة التشغيل أو تعدد مثيلات API ولا تمنع سباقات الطلبات المتوازية.

## القرار

يستخدم API جلسة **opaque Bearer** عشوائية بطول 256 بت. يظهر النص الصريح مرة واحدة فقط في استجابة تسجيل الدخول؛ ويخزن PostgreSQL هاش SHA-256 في `auth_sessions`. لا تستخدم هذه المرحلة JWT أو refresh token أو cookies أو OAuth.

تعمل `AuthenticationGuard` كحراسة عامة default-deny. الطريق العام الوحيد هو health وعمليات التسجيل والتحقق وإعادة الإرسال وتسجيل الدخول والاستعادة وإعادة الضبط المحددة صراحة. يشتق كل متحكم مملوك `ownerUserId` من جلسة Bearer المصادق عليها، ويعامل المورد المملوك لمستخدم آخر كـ404. لا تقبل أي من `ownerUserId` أو `userId` أو ترويسة ملكية يرسلها العميل كمصدر تفويض.

تستخدم بيئة التطوير outbox محليًا خاصًا، بينما تفرض بيئة الإنتاج SMTP كامل الإعداد. تولّد روابط التحقق وإعادة الضبط من إعداد مركزي، وتخزن فقط هاش الرمز. يحتفظ resend بمسار تحقق سابق حتى ينجح تسليم البديل، ثم يبطل اللقطة السابقة؛ ويستخدم قفل صف المستخدم عند أخذ اللقطة لمنع سباقات إعادة الإرسال من ترك صفر رموز فعالة.

تخزن `auth_rate_limit_buckets` عدادات نافذة ثابتة في PostgreSQL، بمفتاح HMAC-SHA-256 مشتق من preimage منطقي كي لا يحتفظ الجدول بالبريد أو عنوان IP الخام. تستعمل الزيادة `INSERT … ON CONFLICT … DO UPDATE … RETURNING` كعملية ذرية. يسجل `RateLimitExceeded` مرة واحدة فقط عند أول تجاوز لكل bucket/نافذة، بمعلومة scope غير حساسة، لتجنب تضخيم دائم للأحداث تحت الهجوم.

## النتائج والقيود

يمكن إبطال الجلسة الحالية أو جميع جلسات المستخدم، وتبطل إعادة الضبط وتغيير كلمة المرور كل الجلسات الفعالة. يحدّث `lastSeenAt` بصورة متقطعة مستقلة عن صحة المصادقة. يرسل API رؤوس `no-store` للبيانات الحساسة، وتحمي وسائط الحالات بـBearer مع `private, no-store` و`nosniff`.

تتوقف هذه المرحلة هنا. لا تتضمن Mobile Authentication أو Expo SecureStore أو UI للتسجيل، ولا JWT أو refresh token أو 2FA أو passkeys أو تغيير البريد أو حذف الحساب.
