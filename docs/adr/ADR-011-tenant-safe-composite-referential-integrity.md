# ADR-011 — Tenant-Safe Composite Referential Integrity

**الحالة:** **SUPERSEDED** — السياق العيادي تاريخي فقط؛ القرار النشط هو الملكية الشخصية وفق [ADR-016](ADR-016-personal-user-ownership-instead-of-clinic-tenancy.md).

> **تنبيه تاريخي:** بقي مبدأ فرض العلاقات المركبة في PostgreSQL صحيحًا، لكن `clinicId` استبدل نهائيًا بـ`ownerUserId` في المنتج النشط.

## السياق

كان نطاق المستودعات بالعيادة يمنع كثيرًا من التسربات، لكنه لم يجعل إدخال طفل بعيادة A يشير إلى أب بعيادة B مستحيلًا داخل PostgreSQL.

## القرار

تحتفظ الكيانات المالكة بـ`clinicId`، وتستبدل مراجع الطفل أحادية المعرف بقيود PostgreSQL مركبة على `(clinicId, parentId) → (clinicId, id)` للحالات والوسائط والمشروعات والوظائف والنسخ والتدقيق. يبقى Prisma واجهة الوصول؛ تفرض SQL اليدوية القيود التي لا يعبر عنها Prisma بالكامل.

## السبب

يجب أن يبقى العزل صحيحًا عند الاستيراد أو أدوات الإدارة أو خطأ مستقبلي في التطبيق، لا عند الالتزام باتفاقية استعلام فقط.

## النتائج

يضيف القرار فهارس فريدة مركبة موجودة مسبقًا ويجعل الترحيل يفشل مغلقًا إن وجد رسم بيانات قديم متقاطع. الاختبارات تتصل بـ PostgreSQL وتحاول إدخالات متقاطعة مباشرة.

## البدائل المدروسة

رُفضت التحقق في TypeScript فقط والمفاتيح الأجنبية أحادية العمود لأنها تسمح بحالة الطفل/الأب المتقاطعة في قاعدة البيانات.
