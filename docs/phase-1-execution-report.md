# تقرير تنفيذ DentPilot Smile Studio — Phase 0 وPhase 1

**الحالة:** مكتمل للمراجعة، مع توقف صريح قبل Phase 2.  
**الإصدار:** 0.1.0  
**تاريخ التنفيذ:** 26 أغسطس 2026.

> تم تنفيذ Phase 0 وPhase 1 فقط. لا يتضمن هذا المستودع AI سريريًا أو مصادقة إنتاجية أو فوترة أو فيديو أو قوالب إنتاجية.

## 1. ما تم تنفيذه

تم إنشاء مستودع TypeScript أحادي بـ pnpm وTurborepo، يحوي تطبيق Expo/React Native وتطبيق NestJS/Fastify وطبقات `domain` و`application` و`contracts`. ينفذ النظام مسارًا عموديًا واقعيًا: ممثل تطوير مركزي، عيادة تطوير، حالة خيالية، رفع صورة مصدر، تحقق خادمي وتجزئة SHA-256، تخزين خاص، مشروع محاكاة وهمي، وظيفة توليد إديمبوتنسية، معالج غير متزامن، أصل ناتج منفصل، إصدار غير قابل للتعديل، وشاشة نتيجة وسجل تدقيق.

الناتج الوهمي بطاقة PNG حتمية من دون إعادة استخدام مرئية لصورة المصدر، وتحمل العبارتين `MOCK OUTPUT` و`NOT A CLINICAL SIMULATION`. لا يمكن تقديمها بوصفها محاكاة سريرية.

## 2. بنية المستودع

| المسار | المحتوى |
|---|---|
| `apps/mobile` | Expo Router، عميل API، شاشات الحالة والمسار والنتيجة، واختبارات RNTL |
| `apps/api` | NestJS/Fastify، Prisma، ترحيلات PostgreSQL، بذور التطوير، محولات التخزين والطابور والمزود |
| `packages/domain` | أخطاء مصنفة، آلة حالات التوليد، وثوابت المصدر/الإثبات |
| `packages/application` | خدمات الحالات والوسائط والمشروعات والتوليد ومنافذ البنية |
| `packages/contracts` | عقود Zod المشتركة لـ API |
| `infrastructure/local` | Docker Compose لـ PostgreSQL المحلي |
| `docs` | نظرة النظام، نموذج المجال، ADRs، وهذا التقرير |

## 3. كيانات المجال وقاعدة البيانات

تتضمن قاعدة البيانات `User` و`Clinic` و`ClinicMembership` و`PatientCase` و`MediaAsset` و`CreationProject` و`GenerationJob` و`GenerationVersion` و`AuditEvent`. كل كيان تشغيلي مملوك يحمل `clinicId`. توجد مفاتيح خارجية، وفهارس للعيادة/الحالة/الوظيفة، وقيد فريد على `(clinicId, idempotencyKey)`، وقيد فريد على `(generationJobId, versionNumber)`.

لا تُخزن الصور الثنائية في PostgreSQL. يخزن `MediaAsset` بياناتها الوصفية وSHA-256 ومفتاحًا خادميًا خاصًا فقط. لا يستقبل العميل المفتاح ولا مسار نظام الملفات.

## 4. الحدود المعمارية المنفذة

يتجه الاعتماد من العميل/API إلى التطبيق ثم المجال. تقوم طبقة البنية بتنفيذ `ObjectStoragePort` و`GenerationQueuePort` و`SmileSimulationProviderPort` والمستودعات. لا تستورد حزمة المجال أي إطار UI أو ORM أو قاعدة بيانات أو SDK تخزين أو AI.

يحمي محول Prisma الملكية بإدخال `clinicId` في واجهات البحث واستعلاماتها. يحمي محول التخزين المفتاح بخطة مسار مولدة خادميًا، ورفض عبور المسارات وكتابة `wx` التي تمنع الكتابة فوق كائن موجود. يعيد API عقد خطأ آمنًا ولا يعيد أثرًا داخليًا أو مسار تخزين.

## 5. التحقق من Walking Skeleton

تم التحقق عمليًا على PostgreSQL محلي من خلال API يعمل على `127.0.0.1:3000`. أنشأ التنفيذ حالة خيالية، ورفع PNG صالحًا، وثبت صورة SOURCE مع SHA-256، وأنشأ مشروع `smile_simulation`، وأنشأ وظيفة وتابعها إلى `succeeded`، ثم أنشأ أصل GENERATED منفصلًا و`GenerationVersion` رقم 1. أظهر استعلام مساحة العمل أحداث `CaseCreated` و`MediaUploaded` و`CreationProjectCreated` و`GenerationRequested` و`GenerationStarted` و`GenerationSucceeded`.

تم إصلاح مسار الإديمبوتنسية إلى `upsert` ذري اعتمادًا على القيد الفريد، لتفادي حالة PostgreSQL المعاملة المُجهضة بعد تضارب فريد. كما تم تشغيل اختبار استمرارية PostgreSQL الذي أثبت أن العيادة A لا تسترجع حالة العيادة B من المستودع.

## 6. الأوامر المنفذة ونتائجها

| الأمر المنفذ | النتيجة |
|---|---|
| `pnpm install` | ناجح |
| `pnpm db:migrate` على قاعدة فارغة | ناجح؛ طبق `20260826000000_init` |
| `pnpm db:seed` | ناجح؛ زرع مستخدم وعيادة التطوير فقط |
| `pnpm lint` | ناجح؛ 5 حزم |
| `pnpm typecheck` | ناجح؛ 8 مهام |
| `pnpm --filter @dentpilot/domain test` | ناجح؛ 4 اختبارات |
| `pnpm --filter @dentpilot/application test` | ناجح؛ اختباران |
| `pnpm --filter @dentpilot/api test:integration` مع `DATABASE_URL` | ناجح؛ اختبار PostgreSQL واحد |
| `pnpm --filter @dentpilot/mobile test` | ناجح؛ 3 اختبارات RNTL |
| `pnpm test` | ناجح؛ اختبار الاستمرارية متخطى في هذا الأمر لأنه لم يُمرر له `DATABASE_URL`، وقد نفذ منفصلًا بنجاح |

| تشغيل API والمسار العمودي عبر `curl` | ناجح؛ أنشأ ناتجًا وإصدارًا وسجل تدقيق |

## 7. نتائج الاختبار والتغطية النوعية

تغطي اختبارات المجال الانتقالات الصحيحة والخاطئة، وعدم تحويل SOURCE إلى GENERATED، ومتطلبات إثبات الأصل. تغطي اختبارات التطبيق الإديمبوتنسية ورفض وسيط مشوه قبل التخزين. يغطي اختبار PostgreSQL عزل المستأجر. تغطي اختبارات React Native إنشاء الحالة وحالة الإرسال وحالة معالجة وظيفة الخادم وحالة الفشل القابلة للتعامل.

تستخدم اختبارات Expo `--forceExit` بسبب مقابض Expo الأصلية التي تبقى حية في بيئة Jest بعد إتمام الاختبارات؛ جميع التأكيدات تمر، لكن ينبغي التحقيق في تلك المقابض عند تحسين بنية الاختبار لاحقًا.

## 8. القيود المعروفة

طابور التوليد داخل الذاكرة ولا ينجو من إعادة تشغيل API، وهو مقصود لـ Phase 1 فقط. التخزين المحلي ليس تخزين إنتاجي ولا يوفر سياسة وصول سحابية أو تشفيرًا مدرًا بالمفاتيح. هوية التطوير ثابتة ولا تقدم جلسة أو دخولًا أو أدوارًا إنتاجية. مسار الهاتف منشأ ومبني للويب ضمن التحقق، لكن لم يُشغل على محاكي Android/iOS في بيئة التنفيذ.

لم تكن Docker متاحة في بيئة التنفيذ، لذلك استُخدم PostgreSQL 16 محلي مثبتًا لتشغيل الترحيل واختبار الاستمرارية. يوجد `infrastructure/local/docker-compose.yml` لبيئات المطورين العادية.

## 9. العمل المؤجل إلى Phase 2 وما بعده

تؤجل Phase 2 المصادقة، الحسابات، العضويات، الأدوار، الجلسات، ودورة حياة الحساب والموافقة. تؤجل المراحل التالية خط أنابيب وسائط الإنتاج، القوالب، بحث/مقارنة مزودي Smile AI، AI الحقيقي، الفيديو، تجربة المنتج المصقولة، الاستحقاقات والفوترة، والتقوية الإنتاجية. لا ينبغي بدء أي منها قبل الموافقة على هذه المرحلة.

## 10. المخاطر المعمارية المكتشفة

أهم خطر متبقٍ هو استخدام طابور ذاكرة محلي؛ لا يصح أن ينتقل إلى الإنتاج. الخطر الثاني هو وجوب استبدال ممثل التطوير بمصادقة تتحقق من عضوية العيادة على كل طلب. الخطر الثالث هو أن سياسة الاحتفاظ/الحذف والموافقة والتشفير ليست منفذة بعد، رغم أن نموذج الأصل والتتبع يهيئ لها. يجب أيضًا تحويل اختبارات Expo لاحقًا إلى إعداد لا يتطلب `--forceExit` قبل اعتماد خط أنابيب CI إنتاجي.
