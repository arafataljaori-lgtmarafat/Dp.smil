# تقرير تنفيذ Phase 2A.1 — Identity & Authentication Core

**الحالة:** منفذ بانتظار بوابات التحقق النهائية.  
**النطاق:** بدائيات الهوية والمصادقة وتدقيق الممثلين فقط.  
**خارج النطاق عمدًا:** التسجيل، الدخول، endpoints للمصادقة، cookies، JWT، OAuth، واجهات Expo للمصادقة، البريد الحقيقي، أو أي ميزة من Phase 2A.2.

## ما تم تنفيذه

| المحور | التنفيذ |
|---|---|
| المستخدم | أضيف البريد الأصلي والمطبع، الحالة، وقت تحقق البريد، و`updatedAt` إلى `users` مع backfill حتمي لحساب Foundation التطويري والحسابات القديمة غير القابلة للتوجيه. |
| بيانات الاعتماد | أضيف `password_credentials` بعلاقة واحد إلى واحد وhash Argon2id فقط. |
| الجلسات والرموز | أضيف `auth_sessions` و`account_action_tokens` بقيم SHA-256 مخزنة فقط، مع صلاحية مطلقة وقيود زمنية وغرض رمز متحقق. |
| الأحداث الأمنية | أضيف `security_events` كأثر منفصل خالٍ من أسرار النصوص الصريحة. |
| التدقيق | استبدل `actorId` بـ`actorType` و`actorUserId` و`systemActorKey` مع CHECK يمنع الأشكال المختلطة أو انتحال العامل النظامي للمستخدم. |
| بدائيات المجال | أضيف تطبيع البريد والتحقق من الصيغة وسياسة كلمة مرور 12–128 محرفًا وفصل الممثل البشري عن النظامي. |
| التشفير | أضيف محول Argon2id v=19 بمعلمات مركزية، ومولد رموز 256-bit URL-safe، وdigest SHA-256. |
| التطوير والـCI | حدثت البذور لهوية شخصية ثابتة، وسجل Pino يحجب مفاهيم الأسرار، وCI يشغل Prisma والترحيلات والانجراف والاختبارات على PostgreSQL. |

## سلامة الترحيل

الترحيل `20260827000000_phase_2a1_identity_auth_core` لا يغير أي ترحيل Foundation تاريخي. يملأ حساب Foundation التطويري بالبريد `dev-user@dentpilot.invalid` وبحالة نشطة وبوقت تحقق، ويملأ المستخدمين السابقين الإضافيين بعناوين `legacy-{uuid}@dentpilot.invalid` بدلاً من اختراع بيانات شخصية. أظهر اختبار ترقية مستقل من ست ترحيلات Foundation إلى الترحيل السابع النتيجة المتوقعة للحساب التطويري: `dev-user@dentpilot.invalid|active|verified`.

> لا تحفظ الجلسات أو رموز التحقق أو الاستعادة بصيغة صريحة في قاعدة البيانات. النص الصريح ناتج لحظي من البدائية، أما القيمة الدائمة فهي SHA-256 فقط.

## مصفوفة الاختبار

| الفئة | التغطية |
|---|---|
| المجال | تطبيع البريد، الرفض التركيبي، سياسة كلمة المرور، وفصل ممثلي الإنسان والنظام. |
| التشفير | Argon2id والتحقق من كلمة المرور و`needsRehash`، entropy الرمز، SHA-256، وصلاحيات الجلسة ورموز الحساب. |
| PostgreSQL | uniqueness للبريد والرموز والجلسات، CHECK للوقت والـhash، credential واحد للمستخدم، أغراض الرموز، وأشكال audit actor. |
| الانحدار | عزل المستخدم وقيود Foundation والرسم المنطقي وسباق الإديمبوتنسية ومسار `GenerationService` المعاملي. |
| الترقية | سلسلة Foundation ثم Phase 2A.1 وPrisma drift parity. |

## معايير القبول

| المعيار | الحالة المتوقعة في التحقق النهائي |
|---|---|
| الترحيلات من قاعدة فارغة ومن Foundation موجودة | يجب أن تنجح بلا reset أو تعديل تاريخي. |
| Prisma schema والانجراف | يجب أن تكون صحيحة و`No difference detected`. |
| اختبارات الوحدة وPostgreSQL | يجب أن تنجح، بما فيها identity constraints والانحدارات السابقة. |
| Foundation walking skeleton | يجب أن يستمر مسار الحالة والوسيط والمشروع والتوليد والتاريخ؛ لا تضاف واجهة مصادقة. |
| حدود Phase 2A.1 | لا endpoint أو cookie أو JWT أو OAuth أو واجهة Auth. |
